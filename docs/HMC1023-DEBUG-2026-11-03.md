# HMC1023 bring-up — RESOLVED, 2026-11-03

_Branch `fix/hmc1023-lpf`. The HMC1023 now receives with gain. Root cause was a firmware bug, not hardware._

## TL;DR

- **The HMC1023 works.** Switched into the RX path with both channels enabled, it passes the
  signal **with gain and beats the hardware-bypass path.** (Two 10 dB stages cascaded = ~20 dB.) It
  sits **ahead of the mixer** (RF preamp), so unlike I first said, its gain CAN help sensitivity —
  see the RF-architecture section for the real chain and the boost-noise tradeoff.
- **Root cause: a one-line firmware bug.** The config wrote `reg1 = 0x12`, which clears
  `filter_I_enable` (bit 2) and `filter_Q_enable` (bit 3). Per the datasheet those bits
  default high and gate the *entire* analog path (gain stage + filter + driver). Writing
  `0x12` held both channels in reset, so the chip passed nothing. Every HMC test before
  today used `0x12`, which is why it always looked dead. Fix: `reg1 = 0x1C`.
- **The overnight "floating VBG / dead analog section" theory was wrong.** VBG (pin 29) is
  "1.2 V bandgap output, testing only" (datasheet Table 6) — floating is *correct*. The
  faint feedthrough seen earlier was signal leaking passively around a disabled chip.
- The Si5338 CLK1A cal-clock fix (MS1 → 40 MHz) stands and is correct, but was **not** what
  was blocking reception — uncalibrated bandwidth (±20%) is fine because the filter corner
  sits far above the QSD baseband.

## The fix (what changed)

- `hmc1023_probe()` reg1 write: `0x12` → `0x1C` (`filter_I_enable | filter_Q_enable |
  force_cal_code`), with a corrected comment. (`Core`/`Source/src/main.c`)
- New `hmc1023_config_rx()`: powers the LPF, enables both channels, +10 dB gain, 20 MHz
  Butterworth corner, filter active (`reg1=0x1C`, `reg2=0x115`), reads back. Proven config.
- New console command **`H`** → runs `hmc1023_config_rx()` and prints the readback, so the
  whole chain is driveable without raw hex pokes.

## HMC1023 register facts that matter (from the datasheet, Tables 17–19)

- **Reg 01h (Enable):** b0 OTP_DontUse · b1 cal_enable · **b2 filter_I_enable (dflt 1)** ·
  **b3 filter_Q_enable (dflt 1)** · b4 force_cal_code (apply SPI bandwidth) · b5 doubler_enable
  (set for CALCK < 40 MHz) · b9 + Reg02h[10] = input impedance select.
- **Reg 02h (Settings):** [1:0] opamp_bias · [3:2] drvr_bias · **b4 gain_10dB (0/10 dB per
  channel — the part's only gain)** · **b5 bypass_filter** · [9:6] coarse_bandwidth_code
  (0000=5 MHz … 0100=20 MHz … 1000=72 MHz) · b10 input-Z MSB.
- **Reg 03h [3:0]** fine bandwidth (needs `force_cal_code`=Reg01h[4]=1 to take effect).
- Gain is **10 dB per channel** (0 or 10); this board cascades both channels for ~20 dB. It's a
  filter/ADC-driver, not a big gain block, and it's post-mixer baseband (no NF benefit). To calibrate
  the corner to ±2.5%: clock 20–80 MHz on CALCK (doubler for <40 MHz), write period (ps) to
  Reg05h, `cal_enable` Reg01h[1]=1, Reg06h[8:0]=0x96, strobe Reg04h, poll Reg08h[4]. Not
  required for operation here.

## RF architecture (netlist trace, PSDR.asc) — corrected

Direct-conversion (zero-IF) **transceiver**; the two ADE-2ASK diode-ring mixers are shared (down-convert
on RX, up-convert on TX). **Correction:** I first mis-traced this — the `74CBTLV3253` muxes (and the
HMC1023) are in the **RF path AHEAD of the mixers**, not in the baseband. Tracing `FILTER_IF`
(-> L82 -> mixer RF ports) and `FILTER_RF` (-> L39 -> antenna) against the mux pins settles it; the
HMC1023's `FILTER_IN`/`FILTER_OUT` are a mux-selectable branch of that RF path.

RX:
```
antenna (ANT/VNA-IN) -> MASWSS0129 switches (U16 amp-insert / U24 bridge-insert / U30 VNA-tap)
  -> L39 balun (SE->diff) -> FILTER_RF
  -> 74CBTLV3253 muxes (U211/U298): straight-bypass  OR  HMC1023 (U287)   <- RF preamp + ~72 MHz roofing LPF, PRE-mixer
  -> FILTER_IF -> L82 balun -> ADE-2ASK mixers (L81=I, L41=Q), quad LO from SY10EP52 (U280/U279)
  -> baseband I/Q -> MAX4525 T/R (U18/U4) -> MCP6N11 in-amps (U272/U255), gain=MAX5388 pot (U15)  <- POST-mixer
  -> STM32F746 ADC (U121.24/.25)
```

The HMC1023 runs far below its 72 MHz corner, as an **active RF preamp + roofing LPF ahead of the
mixer**, two channels cascaded (I-out -> C293/C294 -> Q-in) for ~20 dB.

**Sensitivity implication (revised — opposite of my first take):** because the HMC1023 sits *ahead*
of the lossy mixer, its ~20 dB **can** improve noise figure / MDS — RF gain in the right place. Two
caveats, settled only by measurement: (1) powering it forces on the ADP1613 boost (`LPF_5V` <- Q208 <-
`+5V_BOOST`), the switcher that desensitizes the HF front end, so it's "preamp gain vs switcher noise,"
net empirical; (2) the **MCP6N11 in-amp + MAX5388 gain pot are POST-mixer**, so that gain does NOT
change NF, only ADC level. Bench gain-pot sweep (7 MHz, -50 dBm, CW): swing rises monotonically with
the pot (buried at 0, ~9 at the default 200, ~10.6 at 255) — a small lever, consistent with it being
post-mixer.

TX (shared mixers, reversed):
```
STM32 DAC1/DAC2 (U121) -> MAX4525 DAC mux (U86) -> FAN4174 recon LPFs (U227/U216)
  -> AD8131 diff drivers (U260/U253) -> MAX4525 T/R (U18/U4, net TRX_SWITCH)
  -> ADE-2ASK mixers (up-convert) -> L82 -> muxes -> L39 -> MASWSS0129 (U30/U24/U16) -> antenna
```
- T/R is switched at **baseband** by `TRX_SWITCH` (U18/U4 MAX4525): each mixer IF port goes to either
  the TX AD8131 driver or the RX MCP6N11 in-amp.
- **HMC482 (U304) is the only active RF amp — effectively the "PA"** (otherwise passive up-conversion,
  QRP-level). Netlist oddity: BOTH RF ports carry DC bias (input via L11 choke off an R6/R14 divider,
  output via L19 off +5V_AMP) — atypical for a plain forward gain block, matches the "wired unusually"
  description. Insert/bypass via U16 (two bits, AMP_SWITCH_A/B); which direction it's traversed per U16
  state is NOT resolvable from the netlist. Supply +5V_AMP gated by AMP_POWER.
- **No hardware TX I/Q trim** (MAX5388 pot is RX-only) — carrier/image balance rides on matched passives
  + the two DACs, so correct it in firmware/DAC scaling.

VNA: 1-port vector reflectometer — AD8302 (U314) magnitude/phase detector across a 1% resistive bridge
(R22/R23/R25/R28), switched inline by U24; MAGNITUDE/PHASE -> STM32 ADC. The TX synthesizer doubles as
the source. (Naming trap: the net `RF_ANT` is the bridge's DUT node, not the main antenna line — that's
`ANT/VNA-IN` via U16 -> C303.)

**2 m (144-148 MHz) RX attempt:** with the console F-clamp lifted to 175 MHz the firmware tunes there
(`setFreq` ×2 -> 288 MHz Si5338 LO, /2 in the SY10EP52), but a strong CW tone 144-148 produced ~0 swing
on bypass — nothing heard. Not free: needs a VHF-capable RF front end (and a verified VHF LO); scope the
LO at the mixer / Si5338 output to disambiguate LO-synthesis vs front-end filtering.
