## TL;DR

- I found and fixed a real firmware bug: the **Si5338 never produced a valid calibration clock** for the HMC1023 (its MultiSynth MS1 was left at the power-up default = an illegal divide, so CLK1A put out garbage instead of a 20–80 MHz cal clock).
- I built the tooling to drive and *measure* the whole thing over the USB console (every RF switch + the HMC1023 registers + a **real S-meter**).
- **But the HMC1023 still passes no signal.** Even with the cal clock fixed, the chip re-powered, and every register config tried, the filter path is dead while the chip answers fine on SPI. That isolates the problem to the **analog section not conducting**, and the prime suspect is a **floating bandgap pin (VBG / pin 29)** — a hardware gap in the same family as the missing-VDDBG one you already blue-wired.
- **This now needs the bench, not more firmware.** Priorities for you are at the bottom.

## What's confirmed working

- **Live SPI to the HMC1023** over USB: `R0` reads `0x114080`, register writes verify on read-back. (The earlier `0xFFFFFF` reads were a firmware bug — the CS/MISO pins were only initialized inside the disabled probe; fixed with `hmc1023_io_init()`.)
- **A trustworthy detector.** `passBandRms` (what drives the red S-meter bar) is now exposed over the console. With the −50 dBm VNA tone in the passband vs out of band:
  - **bypass path: bar ≈ 76 in-band, ≈ 66–70 out → swing ~8** (clear signal)
  - **HMC path (ch2): swing ~0** (no signal)
  This is the objective yardstick I used all night (the old `maxAmplitude` is DC-dominated and useless for this).
- **Mux directions** (both muxes U211/U298 share the select lines; `M0`–`M3` sets the channel):
  - `M1` = **bypass** (stock, S1=0/S0=1) — works
  - `M0` = external filter path (parts not fitted — DNF)
  - `M2` = **through the HMC1023, RX direction** (S1=1/S0=0) ← the correct one
  - `M3` = through the HMC1023, TX/forward direction (S1=1/S0=1) — dead for RX
  Confirmed from the netlist (ch2 routes the U298/RF side into the HMC input) and by bench behavior.

## The HMC1023 problem — full diagnosis

The HMC1023 (U287) has had a *stack* of independent issues, which is why it's never worked:

1. **VDDBG (pin 28) had no supply** — only a decap. You blue-wired it to LPF_5V. ✔ (prior session)
2. **No cal clock.** CALCK (pin 11) ← C283 ← Si5338 CLK1A (U241 pin 18). The hardware path is correct, but the Si5338's MS1 (regs 64–73) was never programmed — it sat at the reset default (P1=0 → divide-4 → 2.84 GHz/4 ≈ 710 MHz, which is above the MultiSynth's legal output, i.e. **no usable clock**). `setFreq()` only ever touches MS0 (the LO). **Fixed**: MS1 → divide 71 → **40 MHz** (reg64=0x80, reg65=0x21). ✔ (commit 24f113d)
3. **Firmware never configured/used the chip** — added full console control. ✔

### The decisive result

With #1–#3 addressed, I measured the HMC path every way I could, using the detector, with the tone parked in the passband:

| config (channel 2) | swing (in−out) |
|---|---|
| ch1 bypass (reference) | **~8** (signal) |
| ch2 auto-cal, filter active | ~0 |
| ch2 auto-cal + gain | ~0 |
| ch2 force-cal, coarse=8 (72 MHz corner) | ~0 |
| ch2 force-cal, coarse=4 (20 MHz) | ~0 |
| ch2 force-cal, **LPF bypassed** | ~0 |
| ch2 after re-powering the HMC with the 40 MHz clock up | ~0 |

A 72 MHz corner passes 7 MHz with enormous margin *regardless of calibration*, and LPF-bypass removes the filter from the path entirely — yet **both pass nothing**. So the blocker is **not** the filter cutoff or the calibration. The chip's analog signal path simply isn't conducting, even though its digital/SPI side is alive.

### What I ruled out (all wired correctly, per the netlist)

- **Supplies**: VDDQ1(2), VDDQ2(4), DVDD(16), VDDI1(21), VDDCAL(22), VDDI2(23) all on LPF_5V; VDDBG(28) blue-wired. (And since SPI/DVDD work, LPF_5V is live.)
- **Signal path**: series I→Q filter — IIP/IIN(26/27) → OIP/OIN(19/18) → C293/C294 → IQP/IQN(31/30) → OQP/OQN(6/7). Fully connected.
- **Common-mode bias**: CMI(20)→R286, CMQ(5)→R296. Present.
- **Cal clock path**: CALCK(11)→C283→Si5338 CLK1A. Present (and now programmed to 40 MHz).

### Prime remaining suspect: VBG (pin 29) is floating

**VBG (pin 29) — the bandgap reference bypass — has no net at all in the netlist** (not even a cap). The digital side runs off VDDBG and works (SPI fine); the analog amplifiers bias off the bandgap, and a floating/unbypassed bandgap reference can leave the entire analog section non-functional. This is exactly the shape of the problem (SPI alive, zero analog throughput) and is the same class of bug as the missing VDDBG.

## Firmware cleanup noted for later (not blocking)

- The 40 MHz cal clock now runs **continuously**. It should be **gated** (clock on only during a cal cycle, then off) so it can't inject spurs into the RX front end. Whether it measurably raises the noise floor is unconfirmed, but gating is the right design.
- The `g_bench` override mode + `M`/`L`/`r`/`R`/`P` commands are dev scaffolding; fold the useful parts into a clean "filter on/off + gain" control once the chip actually works.
