# HMC1023 bring-up — RESOLVED, 2026-11-03

_Branch `fix/hmc1023-lpf`. The HMC1023 now receives with gain. Root cause was a firmware bug, not hardware._

## TL;DR

- **The HMC1023 works.** Switched into the RX path with both I/Q channels enabled and
  +10 dB gain, it passes the signal **with gain and beats the hardware-bypass path.**
- **Root cause: a one-line firmware bug.** The config wrote `reg1 = 0x12`, which clears
  `filter_I_enable` (bit 2) and `filter_Q_enable` (bit 3). Per the datasheet those bits
  default high and gate the *entire* analog path (gain stage + filter + driver). Writing
  `0x12` held both channels in reset, so the chip passed nothing. Every HMC test before
  today used `0x12`, which is why it always looked dead. Fix: `reg1 = 0x1C`.
- **The overnight "floating VBG / dead analog section" theory was wrong.** VBG (pin 29) is
  "1.2 V bandgap output, testing only" (datasheet Table 6) — floating is *correct*. The
  faint feedthrough seen earlier was signal leaking passively around a disabled chip.
- The Si5338 CLK1A cal-clock fix (MS1 → 40 MHz) stands and is correct, but was **not** what
  was blocking reception — uncalibrated bandwidth (±20%) is fine because the filter corner
  sits far above the QSD baseband.

## The fix (what changed)

- `hmc1023_probe()` reg1 write: `0x12` → `0x1C` (`filter_I_enable | filter_Q_enable |
  force_cal_code`), with a corrected comment. (`Core`/`Source/src/main.c`)
- New `hmc1023_config_rx()`: powers the LPF, enables both channels, +10 dB gain, 20 MHz
  Butterworth corner, filter active (`reg1=0x1C`, `reg2=0x115`), reads back. Proven config.
- New console command **`H`** → runs `hmc1023_config_rx()` and prints the readback, so the
  whole chain is driveable without raw hex pokes.

## HMC1023 register facts that matter (from the datasheet, Tables 17–19)

- **Reg 01h (Enable):** b0 OTP_DontUse · b1 cal_enable · **b2 filter_I_enable (dflt 1)** ·
  **b3 filter_Q_enable (dflt 1)** · b4 force_cal_code (apply SPI bandwidth) · b5 doubler_enable
  (set for CALCK < 40 MHz) · b9 + Reg02h[10] = input impedance select.
- **Reg 02h (Settings):** [1:0] opamp_bias · [3:2] drvr_bias · **b4 gain_10dB (0/10 dB — the
  only gain the part has)** · **b5 bypass_filter** · [9:6] coarse_bandwidth_code
  (0000=5 MHz … 0100=20 MHz … 1000=72 MHz) · b10 input-Z MSB.
- **Reg 03h [3:0]** fine bandwidth (needs `force_cal_code`=Reg01h[4]=1 to take effect).
- Gain is **max 10 dB** — this is a filter/ADC-driver, not a big gain block. To calibrate
  the corner to ±2.5%: clock 20–80 MHz on CALCK (doubler for <40 MHz), write period (ps) to
  Reg05h, `cal_enable` Reg01h[1]=1, Reg06h[8:0]=0x96, strobe Reg04h, poll Reg08h[4]. Not
  required for operation here.

## Topology note

The HMC1023 is a **baseband I/Q** filter (it has separate I and Q differential in/out, CMI/CMQ
common-mode pins). It sits around the QSD baseband, not at RF, so the coarse bandwidth never
filters the wanted signal — its job here is the +10 dB gain, anti-aliasing, and ADC driving.
